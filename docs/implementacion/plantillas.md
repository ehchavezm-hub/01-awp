# Plantillas descargables

Todas las plantillas usan los **mismos códigos de paquetes, fases, roles y estados** que este plan, e incluyen filas o textos de ejemplo del proyecto tipo (en amarillo en los Excel) que se borran o reemplazan al usarlas en un proyecto real. Cada Excel tiene una hoja **Instrucciones** con su propósito, cómo llenarlo y el significado de cada columna.

!!! tip "Plan completo en Word"
    El plan de implementación completo, con el mismo contenido de estas páginas, está disponible como documento Word: [:material-file-word-outline: Plan_Implementacion_AWP.docx](descargas/Plan_Implementacion_AWP.docx).

## Por qué se incluyen las plantillas adicionales

Además de las plantillas mínimas (registro de restricciones, matriz RACI, seguimiento de paquetes, plantilla de IWP, plantilla de CWP y procedimiento de restricciones), el kit incluye:

| Plantilla | Justificación |
|---|---|
| Definición de CWA | La definición de CWA es el primer entregable AWP de la planificación temprana (procedimiento 1.0, curso 2023). Sin CWA formales no se pueden codificar ni secuenciar los paquetes. |
| Path of Construction | Todas las fuentes coinciden en que la secuencia de construcción debe dirigir la ingeniería y la procura; la plantilla convierte el PoC en fechas requeridas de EWP, CWP y RAS. |
| Programa de liberación de IWP | Aplica el programa típico de restricciones del CII y el *Pack Track* del procedimiento 3.0 a los plazos de cada fase, para detectar a tiempo los IWP que no llegarán liberados. |
| Lookahead de 3 semanas | El *three-week look-ahead* y el PPC son el vínculo entre el backlog y la ejecución semanal (procedimiento 3.0 y comparación AWP–Lean Construction). |
| Checklist de liberación de IWP | Hace verificable la regla de oro de WFP (IWP libre de restricciones) y alimenta el KPI de IWP liberados sin restricciones. |
| Tablero de KPI por fase | Las fuentes piden medir AWP con KPI, pero sus listas se perdieron en la conversión; el tablero fija fórmulas únicas para poder comparar las fases. |
| Registro de riesgos | La implementación tiene riesgos propios (patrocinio, planificadores, secuencia de ingeniería, interfaces entre fases) que requieren seguimiento formal. |
| Registro de lecciones aprendidas | La superposición de fases permite aplicar lecciones casi en tiempo real si tienen dueño, fecha y verificación. |
| Plantilla de EWP | Asegura que ingeniería entregue paquetes completos por CWP y en la secuencia del PoC (relación 1 EWP = 1 CWP). |
| Acta del taller de Path of Construction | El PoC se acuerda en talleres IPP con varias disciplinas; el acta deja constancia de la secuencia, las decisiones y la aprobación (hito H2). |
| Informe de cierre AWP de fase | Es la evidencia del hito H10 y el vehículo formal para transferir resultados y lecciones a la fase siguiente. |
| Perfiles de puesto AWP | Las fuentes insisten en roles dedicados (AWP Champion y planificadores 1:50); la COAA incluye perfiles de puesto en su biblioteca. |

## Cómo se generan

Los archivos se generan con los scripts de `implementacion/scripts/` a partir de datos maestros comunes, lo que garantiza la consistencia entre plantillas. Para regenerarlos después de cambiar los datos del proyecto tipo, consulta `implementacion/README.md` en el repositorio.
